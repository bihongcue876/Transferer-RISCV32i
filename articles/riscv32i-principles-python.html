1 定位与边界

RV32I 是 RISC-V 指令集架构的基础整数部分，由 32 个 32 位通用寄存器、定长 32 位指令编码、四十条基础指令与六条 Zicsr 特权指令组成。本文以它的编解码原理，也就是从汇编语言到机器码转换的基本原理为主线，依次介绍寄存器模型、六种指令格式、立即数排布、编码与译码链路，以及 PC 相对寻址；随后说明本项目与这些原理之间的对应关系。

本项目是一个 Python + Tkinter 桌面应用，采用纯标准库实现，专注于汇编与机器码的双向翻译；执行程序、C 压缩扩展、ELF 文件解析均在其范围之外。在这一边界内，工程上有三处值得认真对待的地方：位域编码、带标签的两遍汇编、行级错误模型。下文围绕这三条线索展开。

2 RV32I 编解码原理

2.1 寄存器与定长编码

整数寄存器共 32 个，记作 x0 至 x31，宽度均为 32 位；其中 x0 的读数恒为 0，写入无效，常量 0 的获取与运算结果的丢弃都借助它完成。程序计数器 PC 同为 32 位。指令编码一律 32 位定长，取指时边界天然确定，各字段的位置随格式固定，这与 x86 等变长指令集形成鲜明对比。体系还有一个特点：比较结果直接写回寄存器（slt、sltu），条件判断交给 beq、blt 等分支指令完成，硬件中省去了独立的标志寄存器。

2.2 六种指令格式

六种指令格式共享同一组字段位置：最低 7 位恒为 opcode，rs1 恒在 19:15，funct3 恒在 14:12，rd 恒在 11:7——S 型与 B 型的写回槽位让给了立即数。公共字段位置固定，取字段与判格式得以同时进行；各格式的差异集中在编码前半段：R 型安排三个寄存器，I、S、B 型携带立即数，U、J 型携带大立即数。

这两张成图转载自 Stephen Dai 的公开教学图，项目学习页采用的也是同源插图（见图 9）；本站图 1 为自绘简化版，二者可对照阅读。

2.3 立即数的排布

图 1 中 B 型立即数的位序初看杂乱，实则是面向硬件的精心安排，理由有三：

  • 符号位固定：立即数最高位恒在指令 bit31，符号扩展的位置固定，加法器进位链得以缩短；
  • 字段对齐：rs1、rs2、funct3 在 R、I、S、B 四种格式中位置一致，一组译码线路即可服务多种格式；
  • 低位省略：分支、跳转类（B/J）的 imm[0] 恒为 0 且无需编码，目标地址天然保持 2 字节对齐（I、S 型无此约定）。

2.4 一条指令的编码链路

一条汇编语句转换为 32 位机器码，经历五个步骤：

  1. 词法切分：剥去注释，摘出行首标签，将语句归一为「助记符 + 操作数」；
  2. 查表判格式：由助记符查指令表，取得格式类别与 opcode、funct3、funct7；
  3. 操作数解析：寄存器名接受 x1 与 ra 两套写法，立即数接受十进制、十六进制与负数，访存操作数采用 imm(rs1) 形式；
  4. 立即数校验与拆位：核对取值范围（I 型 ±2048、B 型 ±4096、J 型 ±1 MiB），再按格式将各段安置进对应位段；
  5. 位拼接输出：各字段左移至规定位后按位或，得到 32 位机器码，再按端序格式化为十六进制或二进制。

2.5 编码实例

以一条典型的 I 型指令演示全过程：addi x1, x2, 100。查表得 I 型、opcode 0010011、funct3 000；x1 映射 rd=00001，x2 映射 rs1=00010，100 展开为 000001100100；按「imm‖rs1‖funct3‖rd‖opcode」的次序拼接，得到 32 位字 0x06410093。各字段的宽度与位置均由图 1 的格式表规定，汇编器的工作归结为查表与拼接。

S 型指令的转换另有两处变化：负立即数与访存格式。以 sw x5, -8(sp) 为例，imm = −8 拆成 [11:5] 与 [4:0] 两段分别安置，寄存器采用别名 sp（即 x2）。

2.6 译码

译码是编码的逆过程，次序却另有讲究：先由 opcode 判定指令族，再以 funct3（R 型与移位指令还需核对 funct7）在族内确定唯一指令，最后拆出 rd、rs1、imm 拼回操作数。整个过程遵循「先定型、再取值」：opcode、funct3、funct7 的组合在表中查无对应时，结果记为无法解码——对译码器而言，误判比报错更危险。S、B、J 型的立即数按图 4 的映射逆向拼回。

2.7 PC 相对寻址

分支与跳转指令携带的是相对偏移而非绝对地址，目标地址按「pc + imm」计算，imm 以 2 字节为单位——这正是 imm[0] 无需编码的原因（见 2.3）。采用相对寻址后，代码段整体搬移时分毫未改依然成立，补丁与链接工具也省去了重算绝对地址的工作。偏移范围有限：B 型为 ±4 KiB，J 型为 ±1 MiB，更大的跨度需要 auipc 先行取高位。

3 与本项目的关系

原理为体，工程为用。第 1 节列出的三个难点，在本项目中各自落实为一项设计：

3.1 难点一「位域编码」：表驱动

图 1 的格式表在代码中呈现为一张字典，每条指令记录 type、opcode、funct3、funct7 四项属性；encode 依表拼位，decode 依表精确匹配（2.6）。六种格式与伪指令在代码中的落点一一对应：

RV32I_INSTRUCTIONS = {
    "add":  {"type": "R", "opcode": 0b0110011,
             "funct3": 0b000, "funct7": 0b0000000},
    "addi": {"type": "I", "opcode": 0b0010011, "funct3": 0b000},
    # …共 40 条基础 + 6 条 Zicsr（CSR）
}
  • R、I、S、B、U、J 六型分别对应 encode 中的同名分支，位拼接各成一套（2.4 第 5 步）；
  • 访存与跳转变体：lb 至 lhu 归入 I_LOAD 分支，jalr 归入 I_JALR 分支；
  • ecall 与 ebreak 归入 I_SYSTEM 分支，以 imm12 区分；六条 CSR 指令归入 I_CSR，fence 归入 I_FENCE；
  • 27 条伪指令独立成表，先展开为基础指令序列，再进入 encode。

3.2 难点二「两遍汇编」：标签、锚点与 hi/lo

真实程序中常见 loop: 这样的前后引用，单次扫描难以同时确定偏移与地址，因此采用经典的两次扫描：第一遍摘取标签，按伪指令展开统计每行的 4×n 字节并分配地址，人工填写的地址作为绝对锚点保留，锚点之间的空隙宁可留白；第二遍逐块编码，将标签替换为「目标 − pc」（见 2.7）。

la、call、tail 三条伪指令的目标可达任意 32 位地址，超出单条指令立即数的表达范围，处理办法是拆分高低两段：高 20 位装入 auipc，低 12 位装入 addi 或 jalr，加 0x800 的修正将进位折入高位。

hi = ((off + 0x800) >> 12) & 0xFFFFF   # 高 20 位
hi_signed = hi - 0x100000 if hi & 0x80000 else hi
lo = off - (hi_signed << 12)           # 低 12 位 ∈ [-2048, 2047]

3.3 难点三「行级错误」：错误模型与测试

错误信息的粒度定为「行」：未知指令、无效寄存器、立即数越界、未知标签、重复标签均以行级错误对象返回，汇编过程照常推进；界面上对应行在汇编列与机器码列同时标红，底部给出原因。工具整体构建于 Python 标准库与 Tkinter 之上——转码的可信度系于每一个 bit，依赖越精简，核对越彻底。测试以 unittest 覆盖三类性质：手册样例的逐位核对、encode 与 decode 的往返一致（图 5 与图 7 互为逆过程）、标签与锚点的边界情形。转码页与学习页均建立在这些基础之上，后者将上述原理整理为可操作的教材。
